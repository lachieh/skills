## Why `correct` is its own skill

`principle-encode-lessons-in-structure` is the in-task rule: when a correction
recurs, encode it, types and checks before prose. `automate-me` mines session
evidence for a personal mode skill. `reflect` reviews one active session
through three lenses and, with approval, edits skills. Its structural step
records a mechanism and does not implement it.

`correct` reads commits, reverts, review comments, and agent instructions,
then lands one repository change per mistake class and proves the new check
fails on a past instance. Putting that procedure inside `reflect` would give
one skill two jobs and would contradict `reflect`'s rule that structural
prevention is reported rather than applied. The new skill states the order
structure, types, lint, tests, then docs, and points at the principle only for
a helper or automation that order does not name.

## Trim

PR 419 removed two `tdd` lines that restated rules the local skill already
enforces. The introduction already skips an impractical test and uses the
closest check. The final response already requires the reason when a
failing-before test was not run. The guardrail against a weak-signal test
repeated "prefer no new test over a bad test." Those two lines are gone. The
examples of the closest check stay.

The other cuts in PRs 538, 571, and 419 delete upstream tutorials, evidence
checklists, return-format blocks, and principle essays. The local skills were
rewritten in the original adaptation and do not carry those sections.
`figure-it-out` still says to inspect artifacts, because that sentence also
carries the weak-observation rule the upstream edit kept. `interrogate`'s
reviewer prompt states style, hypothetical, and rewrite limits once. Removing
them would drop the standard. `principle-prove-it-works`,
`principle-never-block-on-the-human`, `principle-guard-the-context-window`,
`principle-encode-lessons-in-structure`, and the `why` source guide are
already short contracts, so they were left as they are.

## PR 491 changes left out

Fresh-subagent defaults, plain-language alternatives to a reply token, the
hourly autopilot tick, pull-request heading rules, and the schema-first Zod
example belong to upstream playbooks and TypeScript notes. Local delegation
already reviews a delegate's diff. `principle-never-block-on-the-human` already
keeps reversible work moving. `technical-writing/references/pull-requests.md`
already sets the pull-request contract. `typescript-best-practices` already
requires a parser or schema at an untyped boundary. None of those upstream
edits fixes a hole in the local text.
