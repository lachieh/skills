## Adopted from PR 633

`e5136d82418d2db3165ea1050d17577cd618cc05` restates four principles and the
test step in `correct`. Two of those edits land here, in local wording.

`principle-make-operations-idempotent` keeps its retry rule. One further rule
follows it: a lock, temporary file, or half-written record left by a run must
be recognizable as stale by the next run wherever the last run stopped. The
example is a write to a temporary path renamed into place. The upstream essay
about claimed jobs, PID locks, and content comparison stays upstream.

`correct` step 3 no longer uses the "returned nothing" probe. A test that
still passes when the behavior it checks breaks, or that fails when only the
internals change, is fixed or deleted.

## Open questions

These are not decided.

- **PR 700.** Upstream brands through a verifying type guard and returns the input with no `as`. The local patterns example still validates and returns `input as AgentId`. `typescript-best-practices` treats every `as` as a proof obligation and allows one after validation. Whether a brand must come from a type guard, with no cast, is open.
- **`/sharpen`, PRs 615, 712, and 729.** PR 615 added a manual skill that sharpened the task and then did the work, and it forbade handing back a rewritten prompt. PR 712 removed that ban. PR 729 replaced the body: four questions about expert practice, raw material, methods, and an outside check, then a rewrite of the prompt and nothing else. Whether to add that skill is open.
- **`/in-your-own-words`, PRs 602 and 606.** PR 602 restated the goal and waited for confirmation. PR 606 removed the wait. The current text restates the user's goals and the problem they are solving. Whether to add that skill is open.
- **`/ketchup`, PRs 609, 628, 692, 708, and 616.** The current skill catches the user up since their last message, in the voice of `bro`, with screenshots, videos, and diagrams, and lists every item waiting on them so the reply alone can decide it. It does not drop items to stay under a word count. PR 616 only points the autopilot playbook replies at that skill. There is no local autopilot playbook. Whether to add the skill is open.
- **Formal verification, PRs 709, 721, 716, and 715.** PR 709 adds `create-formal-verification-skill`. PR 721 makes TLA+ the default for event-order questions and falls back to generated inputs when no verifier runs on the language. PR 716 adds `maintain-formal-verification-skill`, which updates the verification and does not edit product code unless asked. PR 715 offers the pair from `setup-pstack` and the guide. `create-verification-skill` remains the local behavioral check. Whether to add the formal pair is open.
- **PR 238, ready versus draft.** The opening-a-pr playbook says to open every pull request ready, never as a draft. `shipit` does not say. Whether the local procedure should require a ready pull request is open.
- **PR 414, `log.sh`.** The hunk writes the header with `>>` when the file is missing or empty, so a failed existence check cannot truncate rows that are already there. Local `show-me-your-work/scripts/log.sh` still uses `>` after `[ ! -f ]`. That hunk is not a model slug. It was not applied with the rest of this skip. Whether to take it is open.
