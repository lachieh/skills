# Experience First

The product is the experience. Identify what the user is trying to achieve and
the outcome we want for them, then choose a solution where those goals reinforce
each other. When implementation convenience conflicts with the user's
experience, choose the experience. Complete the core loop before expanding
breadth.

## Find the goal

Use `principle-fix-the-latent-issue` to distinguish the requested intervention
from the underlying need. If either goal is unclear, find out through context,
observation, prototypes, or a direct question when the judgment belongs to the
user.

## Make product choices

Say no to features, controls, and options that do not serve the core loop. Ship
fewer complete capabilities rather than more rough ones. Sweat feedback, error
states, recovery, transitions, and the other details the user encounters.

When experience depends on feel, use `principle-exhaust-the-design-space` and
compare concrete prototypes before committing.

## Know the user

The user is whoever consumes the work: the end user, the colleague using the
API, the operator running the system, or the engineer maintaining it next.
Foundations serve their experience, not the other way around.
