# Evidence sources

Use the categories available through the current host and authorized tools.

## Source control

Search file and symbol history through renames, blame relevant lines, inspect
introducing and corrective commits, and read linked pull requests and reviews.
This is the only category expected for every Targeted investigation.

## Issues and project tracking

Search target names, user-facing terminology, commit identifiers, pull-request
links, incident identifiers, and surrounding dates. Inspect parent and sibling
work when they define the product or business constraint.

## Long-form documents

Search decision records, RFCs, specifications, product requirements,
postmortems, meeting notes, and linked documents. Record alternatives and
constraints in the source's words.

## Team chat

Search target names, symbols, links, incident channels, authors, and the decision
window. Preserve message links and thread context. Do not expose unrelated
private discussion.

## Infrastructure observations

Search metrics, logs, monitors, traces, dashboards, and incidents around the
decision window. Match code constants and behavior to observations without
assuming correlation proves motivation.

## Error tracking

Search stack traces, releases, issue timelines, and errors through the target
path. Check whether first-seen, spikes, and resolution windows align with the
change.

## Product data

Search usage, experiment exposure, feature flags, distributions, scale, and
billing or migration data relevant to the question. Record queries, windows,
counts, and limitations.
