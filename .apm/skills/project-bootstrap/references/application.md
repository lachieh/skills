# Application

The shared packages and the server application. Files named below with a
`templates/` path are copied from there.

## packages/db

SQLite through `better-sqlite3` and Drizzle ORM. Migrations are generated by
drizzle-kit and checked in.

```text
packages/db/
  drizzle.config.ts     dialect sqlite, schema ./src/schema/index.ts, out ./drizzle
  drizzle/              generated migrations, committed
  src/index.ts          templates/packages/db/src/index.ts
  src/migrate.ts        templates/packages/db/src/migrate.ts
  src/repair.ts         templates/packages/db/src/repair.ts
  src/seed.ts           seedReferenceData(database): idempotent reference rows
  src/schema/           one file per aggregate, index.ts re-exports
  src/testing/          templates/packages/db/src/testing/migrated-database.ts plus scenarios
```

Exports: `.`, `./schema`, `./testing`. Dependencies: `better-sqlite3`,
`drizzle-orm`, `effect`; dev: `drizzle-kit`, `@types/better-sqlite3`.

`createDatabase(source: string | Buffer)` opens the connection, sets
`foreign_keys = ON`, and returns `{ database, close }`. Accepting a `Buffer` is
what lets tests open a copy of a serialized image.

`migrateDatabase` wraps `drizzle-orm/better-sqlite3/migrator` with
`migrationsFolder` resolved from `import.meta.url`, so it works from source and
from the container.

`src/testing/migrated-database.ts` builds the migrated image once per process:
open `:memory:`, set the same pragma, migrate, `sqlite.serialize()`, cache the
`Buffer`. `createMigratedDatabase()` opens an independent copy. Replaying
migrations costs seconds on a loaded runner; opening a copy costs about a
millisecond.

Seed scenarios live beside it and are exported from `./testing`. Vitest and
Playwright both consume them, so a scenario is written once.

A different database is a deliberate departure: replace this package's adapter
and the `sqlite-*` infrastructure files, and keep the ports.

## packages/ui

shadcn components with Tailwind. Exports `.`, `./globals.css`
(`src/styles/globals.css`), and `./lib/utils`. Dependencies:
`class-variance-authority`, `clsx`, `tailwind-merge`, an icon library, and font
packages. `components.json` sets `"rsc": false`, `"cssVariables": true`, and
aliases under `<scope>/ui/*`. Ask the user for the shadcn preset.

The package has no `test` script and no Vitest config. Component tests live in
the application that renders them.

## apps/server

TanStack Start on Vite with React and Tailwind. Dependencies:
`@tanstack/react-start`, `@tanstack/react-router`, `react`, `react-dom`,
`effect`, `drizzle-orm`, `zod`, and the workspace packages. Dev:
`@tailwindcss/vite`, `@tanstack/router-plugin`, `@vitejs/plugin-react`,
`@effect/vitest`, `@testing-library/react`, `@testing-library/user-event`,
`@testing-library/jest-dom`, `jsdom`.

Scripts: `build` is `vite build`, `dev` is `vite dev`, `serve` is
`nub server-entry.ts`, plus `lint`, `test`, and `typecheck`.

`tsconfig.json` extends `@repo/tsconfig/react.json`, maps `@/*` to `./src/*`,
and includes `src`, `scripts`, `server-entry.ts`, the Vite and Vitest configs,
and `routeTree.gen.ts`.

`vite.config.ts` plugins, in order: a small plugin that migrates the
development database in `configureServer`, `tanstackStart()`, `tailwindcss()`,
`react()`. Set `resolve: { tsconfigPaths: true }` and `server: { port: 3000 }`.

### Layers

```text
src/
  application/      use cases and ports. Effect only, typed errors
  infrastructure/   adapters: sqlite-*.ts repositories, disk and network clients
  runtime/          composition root: config, layers, ManagedRuntime
  server/           transports: server functions, auth edge, API handlers
  routes/           file-based TanStack routes, flat dotted names
  components/       React components
  features/         self-contained client features
  router.tsx        createRouter({ routeTree, scrollRestoration, defaultPreload: 'intent' })
```

Dependencies point inward: `routes` and `server` call `runtime`, `runtime`
wires `infrastructure` into `application`, and `application` imports neither.

- **application**: each use case is an `Effect` over a repository port declared
  in the same file. Failures are `Data.TaggedError` classes. First-party
  `async`/`await` is absent here.
- **infrastructure**: one adapter per port. Drizzle queries live only here and
  map storage failure to the port's typed error.
- **runtime**: one file per use-case family that provides the adapters and
  exposes `load<Thing>Effect(...)`.
- **server**: `createServerFn` handlers validate input, resolve the session,
  and call `runServerEffect(...)`. They hold no business rule.

A route's colocated non-route file takes a `-` prefix (`-index.helpers.ts`) so
the route generator skips it.

### Runtime

Copy `templates/apps/server/src/runtime/` (`config.ts`, `sqlite-connection.ts`,
`server-effect.ts`, `owner-resources.ts`, `server-lifecycle.ts`) and
`templates/apps/server/src/server/database-url.ts`.

`runtime/config.ts` reads the environment only through Effect `Config` and
publishes it as `Context.Tag` services:

- `ServerConfig`: `DATABASE_URL`, `HOST` (default `127.0.0.1`), `PORT`
  (default `3000`), `NODE_ENV`, media and feature settings.
- `AuthConfig`: origin from `APP_URL`, `BETTER_AUTH_SECRET` as `Redacted`,
  `TRUSTED_PROXY_CIDRS`, `RATE_LIMIT_ENABLED`.

Each loader maps every failure to one tagged error such as
`ServerConfigUnavailable`. Production without `BETTER_AUTH_SECRET` fails
config loading, so a misconfigured container refuses to boot.

`runtime/sqlite-connection.ts` is a `Layer.scoped` that opens the database with
`Effect.acquireRelease` and closes it on disposal. The opener is a parameter so
tests inject an in-memory database.

`runtime/server-effect.ts` composes config, connection, and service layers into
one `ManagedRuntime` and exports:

- `createServerRuntime(overrides)` returning `{ runtime, dispose }`.
- `runServerEffect`, the process-wide runner the server functions call.
- `runServerEffectWithOwner(owner)`, for an entry that owns its own runtime.

`runtime/owner-resources.ts` caches expensive per-runtime objects (the auth
instance, the MCP configuration) keyed on the runtime owner and a symbol. Keying
on configuration instead would make two identically configured runtimes share
one connection.

`runtime/server-lifecycle.ts` exports `startServerDatabase()`: load config,
open, migrate, seed reference data, return the config. Both the Vite plugin and
the production entry call it. Outside production, with `DATABASE_AUTO_RESET`
on, a database whose schema diverged from the migration chain is archived
beside itself and rebuilt from zero.

Tag identifiers use the scope: `Context.Tag('<scope>/ServerConfig')`.

### Gateway entry

`apps/server/server-entry.ts` is a hand-written `node:http` server in front of
the TanStack build. It is the production process and the process the e2e
fixture spawns. Copy `templates/apps/server/server-entry.ts` with
`templates/apps/server/src/server/client-address.ts` and `media-storage.ts`,
then delete the `[module: …]` blocks of unselected modules as its header
describes. Dispatch order:

1. `/assets/*` from `dist/client/assets`, immutable cache headers, with a
   resolved-path check against traversal.
2. Uploaded media and other files in `dist/client`.
3. Agent-readable surfaces, when that module is selected.
4. `/mcp` and `/.well-known/mcp/server-card.json`, with the MCP module.
5. `/api/resources`, with the operator API module.
6. `/api/auth/*` and `/.well-known/oauth-protected-resource`, with Auth.
7. Everything else: `app.fetch(request)` from `./dist/server/server.js`.

Behaviours to keep while porting:

- **Client address.** Forwarded headers are believed only when the socket peer
  matches `TRUSTED_PROXY_CIDRS`. Otherwise they are stripped and
  `x-forwarded-for` is set to the socket address. The rate limiter keys on this
  address, so an unchecked header lets a caller mint a fresh bucket per request.
- **Set-Cookie.** `Headers.entries()` folds repeated `Set-Cookie` values into
  one comma-joined string. Forward `headers.getSetCookie()` as separate headers.
- **Origin.** Build the request URL from `x-forwarded-proto` and
  `x-forwarded-host`, falling back to `host`.
- **Startup line.** Log `<Project> server listening at http://host:port`. The
  e2e fixture matches `server listening at` to learn the port.
- **Shutdown.** On `SIGINT` and `SIGTERM`: close idle connections, close the
  server, dispose the runtime, and force-close after one second.
- **Errors.** A handler rejection answers `500` with a JSON body, or `503` for
  a typed unavailable error, and never crashes the process.

### Storage

The database file and uploaded media live on local disk (`DATABASE_URL`,
`MEDIA_STORAGE_DIR`). A deployment therefore needs one persistent volume and
runs as a single instance.
