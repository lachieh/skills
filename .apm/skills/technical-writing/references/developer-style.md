# Developer style

- Address the reader directly when they perform the action.
- Use present tense for current behavior.
- Write instructions as commands.
- Put a condition before the instruction it controls.
- Put the common case before exceptions.
- Name the actor when the actor matters.
- Use the short everyday word unless a technical term is more precise.
- Use the repository's real symbol, path, flag, command, and domain name.
- Give one name to one concept throughout the artifact.
- Make headings state the point or task.
- Use numbered lists for sequences and bullets for unordered sets.
- Keep list items grammatically parallel.
- Introduce links with text that says where they lead.
- Give code examples enough context to run or understand them.
- State expected output after an action when the reader needs it to continue.
- Put warnings before the action that creates the risk.
- Do not call a task easy, quick, or simple. Give the actual steps and cost.

Pull-request descriptions and commit messages use these sentence rules, but they
do not need a document mode. Product interface copy uses the product's own copy
rules.
